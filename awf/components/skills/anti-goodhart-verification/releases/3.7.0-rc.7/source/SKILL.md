## rc.3 interface changes and remaining limits

- G5r now generates two translated/scaled pairs of geometries. In each pair only the far sphere radius changes; a radius-blind operator must fail. It requires keyword inputs `points`, `centers`, `radii`, `c_min`; `geometry_argument_names` may map these four semantic names to the operator's names. Geometry and expected values cannot be supplied by the caller. Unsupported interfaces fail closed and need a thin adapter. Existing caller probes remain additional checks. Tolerance must not exceed `1e-3 * min(1, partition_total)`, preventing tiny normalization from hiding radius blindness.
- G5n checks magic numbers by default. A deliberate legacy call may set `check_magic_numbers=False`; this is an explicit opt-out, not an equivalent assurance level. Use `allowed_numeric_literals` for justified constants.
- Pair-diff checks removed functions and removed control-flow nodes even below McCabe 5. Legitimate equivalent simplifications can trigger review; this is a structural safeguard, not a semantic-equivalence proof.
- Public gate numeric arguments, numerical conversions and executed callback outputs reject NaN and positive/negative infinity with an exception. Explicit `TensorSpec.domain` infinite bounds remain allowed, and deliberate NaN adversaries remain tested. Failure rewards may still be `-inf`; they are not valid numerical evidence.
- Numerical coverage is reported by the current release validation receipt; it is not a fixed case-count target. This is bounded coverage, not proof about every third-party object, private helper or execution path. Static AST gates do not execute an operator or certify its numerical output. G6o's source-only callback is explicitly excluded from output poisoning.
- Repository verifier `tool.awf-repository-verifier@1.0.0-rc.2` requires Tier 2, all 14 unique slots and all 74 named subchecks from an independent policy, consistent counts and at least 44 negative controls. This policy is schema-pinned: future changes to required subchecks need a verifier successor. Tier-1 engine receipts remain partial and cannot satisfy repository acceptance.
- Finite canonical probes cannot prove correctness against arbitrary adaptive/hardcoded adversaries. G3k still uses caller-supplied probes. An algorithmically independent oracle remains required for meaningful target validation.
- rc.5 removes the W1/W2 file-size waivers. Test-role numerical fixtures remain explicitly listed by relative path; this is separate from file/function size, which has no exemption.

## rc.6 functional architecture and size policy

Use `from awf_guard.api import ...` for supported Python imports. `public-contract.json` declares the 83 supported names. The original `awf_universal_anti_goodhart_gates.py` import and CLI entry point remain compatible; its historical private exports are transitional implementation details. See `ARCHITECTURE.md` for responsibilities and maintenance guidance.

Function length and file length are **advisory by default**. Self-audit lists functions above 200 lines and files above 1000 lines under `size_review_items`; these observations alone do not produce FAIL and require no waiver. Explicit `max_lines`, G6o `min_lines`/`max_lines`, `max_atom_lines`, self-audit `max_fn_lines`/`max_file_lines` remain enforced. Purity, dataflow, complexity, contracts, numerical correctness and anti-cheating checks still apply. Small functions are not inherently better: split when responsibilities, invariants or change reasons differ, and keep one cohesive operation together.

Self-audit covers all nested `.py` files regardless of size. Test-role exceptions cover fixture numeric literals only, not skipping files. Recursive tests prove that a long file/function can pass for length alone while a real violation at its end is still detected. There are no W1/W2 file-size waivers.

Runtime stages are ordinary functions composed by the engine. `execute_stage` holds a stage's evidence locally, rejects unregistered labels and overwriting existing fields, and commits successful evidence once. Failed stages do not partially commit evidence. This is an in-process stage contract, not a distributed transaction; diagnostic callbacks and external side effects are outside that commit boundary.

The calibrated geometry/statistics/matrix scenarios now have functional owners. Correct geometry fixtures are shared independently of the negative-control runner. The coupled-operator/declarative scenario stays together because both checks intentionally exercise the same physical fixture. Historical integration groups remain where they run a shared end-to-end scenario; file counts and private ownership are not acceptance criteria.

Mutation and NaN campaigns replace actual function-object bindings across all loaded release modules. Acceptance still requires all 14 slots, 74 named subchecks, 44 known-wrong cases, strict contracts, fail-closed numerical behavior and detection of every verdict-function force-PASS mutant. The runtime-budget utility is a declared non-verdict mutation exemption, separate from W1/W2. Finite tests are not a proof against all cheating.

## rc.7 evidence hardening

- G7h requires a nonempty concrete list/tuple of input mappings, records requested and executed comparisons, and rejects identical/unwrapped/partial/same-code target and reference origins. Distinct origins are a necessary check, not a proof of algorithmic independence.
- G6p requires at least one candidate and one evaluation input, rejects same-origin reference reuse, and records actual comparisons for every candidate plus the oracle tolerance. Zero evaluations cannot produce a successful candidate.
- G6n requires an existing source file and an audit set containing that file. Empty enumeration cannot pass. All files retain normal static scans.
- FalseGreen ignores lexically unreachable assertions (known false branches, early exits and uncalled nested definitions), checks locally replaced assertion helpers, and labels its assurance as a static heuristic. It does not claim to prove arbitrary runtime reachability.
- Test filenames and `test_` function names no longer grant magic-number exemptions. `fixture-numeric-policy.json` contains explicit numeric allowances and SHA256 pins for reviewed local fixtures; allowances apply only inside this release's physical scripts directory with matching bytes. A changed file loses its allowance until separately reviewed. `refresh_fixture_policy.py` is a development action, never a validation/runtime auto-baseline step.
- G6o requires explicit condition-number and invariant-count declarations, marks them `caller_declared_not_independently_measured`, rejects unavailable source, and validates exact upstream states plus a matching nonempty Tier-1/2 PASS receipt. Manifest registration stores canonical `PASS`; old descriptive status strings must be migrated explicitly. Receipts are trusted caller data, not cryptographic execution attestations.
- Verifier `1.0.0-rc.2` keeps the 14-slot/74-name requirements and checks nonempty execution counts, selected-candidate evidence, the current assertion-analysis mode and nonempty self-audit coverage. Old label-only receipts cannot satisfy this current policy; historical releases retain their frozen verifier.
